# Agent skills and tickets

Requirements, tickets, `expect.yml`, and how project skills are written and published.

- Requirements authoring (`write-requirements` skill; committed project skills live in `.agents/skills/`, not `.cursor/skills/`): write to `.lumpcode/lumps/<lumpName>/backlogItems/todo/<kebab-name>/requirements.md`; specify contracts (signatures, schemas, config/data shapes, CLI syntax, JSON envelopes), not code snippets; name canonical owners for shared concerns (compat shims, filters, path helpers) so staged backlog agents do not duplicate them; pin product shape and avoid over-prescribing incidental types/algorithms (`Map` vs `Record`, regex vs manual matcher) unless load-bearing; requirements document must be a fully decided plan with **no "Open questions" section** — ask the user to resolve ambiguity before writing. Multi-slice or gated work uses `write-tickets` (`.agents/skills/write-tickets/`): tracer-bullet `desc.yml` items with `dependsOn` blocking edges (nested `todo/<parent>/tickets/` when the parent is an umbrella), plus a general feature `requirements.md`; a single fully-decided feature stays on `write-requirements` only
- `expect.yml` (next to ticket `desc.yml`; formerly `blast.yml`, all renamed): scope contract before impl — top-level `desc`, `files` map of repo-relative paths, per-file `desc`, optional quoted `"-"` / `"+"`, optional `symbols` (`create` | `update` | `delete`, not exhaustive). Human reviews the expectation before code; the `backlog` lane's `testImpl` / `impl` prompts point at the file (`prefer the listed files and stay close to the line estimates`). Triptych's Expect plugin parses the same shape. Split the ticket if the file list does not fit in one head. Legacy path-as-root + `change` files still review; new writes use the `files` / `symbols` shape
- Agent skills: author **user-facing** (omit internal "assume the agent lacks the codebase/AGENTS.md" framing); commit project skills to `.agents/skills/<name>/SKILL.md` (Cursor scans `.agents/skills/`; prefer over personal `~/.cursor/skills/`; never `.cursor/skills/` or reserved `~/.cursor/skills-cursor/`); self-contained skills link to GitHub docs (`https://github.com/lumpcode/lumpcode/blob/main/packages/apps/cli/DOCS/...`); prefer directing users to `lumpcode lump-plan` for config validation over shipping bundled validator scripts; project `grilling` skill stress-tests plans one question at a time and drives toward precise interfaces (types, schemas) before implementation; project `write-tickets` skill breaks a plan into tracer-bullet backlog `desc.yml` items with blocking edges; project skills to draft `expect.yml` and review a branch against it are being rewritten (the old `create-blast` / `blast-review` were removed); project `be-honest` skill for opinion/schema questions (honesty with guardrails; not in `PUBLIC_SKILLS`); published skill is `lumpcode` (`.agents/skills/lumpcode/`); `npm run publish-skills` copies `PUBLIC_SKILLS` (`scripts/public-skills.mjs`) to `lumpcode/skills` (`npx skills add lumpcode/skills`); internals stay repo-local
