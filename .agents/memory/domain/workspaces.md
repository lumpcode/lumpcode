# Workspaces and pre-flight

Execution and branch workspaces, checkout versus worktree, pre-flight, the open-branch cap, and `clean`.

- **Execution workspace** (`executionWorkspacePath`): `getExecutionWorkspacePath` both modes = `sourceProjectRoot`. Shared `run`: no git in `setupWorkspaceFn` / `teardownWorkspaceFn`; `branchFn` = current branch; `gitAddCommitFn` / `gitPushFn` no-ops; no auto commit/push. Review (`c`/`e`) only in `commands/run` after success. Dedicated: operator checkout + preflight reset + `lump/…`
- **Branch workspace**: mapped to core `workspacePath` via `makeLumpWorkspaceFns` → `setupWorkspaceFn` (checkout or worktree; not `runProjectPreflight`); path from `branchWorkspacePath` (`mode` + `workspaceStrategy`; shared always the execution checkout); worktrees at `.lumpcode/worktrees/<branch-as-nested-dirs>/` under execution workspace (CLI-only; engine `cwd` stays source `projectRoot`)
- Checkout strategy: `atDirectory(executionWorkspacePath, …)` (`cd /d` on win32). Worktree strategy: `git -C <executionWorkspacePath>`, `shellSingleQuote` on slash branch names, `shellBestEffort` for best-effort steps, platform-specific rm, `mkdir` worktree parent before `git worktree add` on Windows
- **`runProjectPreflight` / `runPreflight`**: execution-workspace only — `git fetch --no-write-fetch-head origin <branch>` / switch / hard-reset (no pull); fetch/switch/reset and dedicated `expandPrimaryBranches` `ls-remote` use `DISCOVERY_GIT_TIMEOUT_MS` (5 min; not `countOpenLumpBranches`); `listRemoteHeadBranches` returns Result (`reason: 'timeout' | 'exit'`) — expand fails the tick only on timeout, other ls-remote failures skip the glob like empty; `countOpenLumpBranches` / `clean` treat `!success` as `0` / `[]`; no branch-workspace preflight. Lump-run hook in `withWorkspaceLockHooks` targets **`resolvedBaseBranch`** (not `resolvedDiscoveryBranch` except when they coincide); daemon discovery uses a separate call with **`scanBranch`** in `discoverDedicatedLumpsForScanBranch`. Preflight and other Lumpcode git mutations take **`gitCommonDirLock`** (`~/.lumpcode/git-common-dir-locks/`, busy code `gitCommonDirBusy`; daemon `wait`, manual `fail`) keyed by `git rev-parse --git-common-dir` — path locks alone do not cover the shared object DB
- Shared `run` allows a dirty tree; dedicated mode can wipe uncommitted work
- `maximumNumberOfConcurrentBranches`: enforced only in dedicated `runLumpFromJsConfig` via **`evaluateTooManyOpenBranchesSkip`** (`countOpenLumpBranches` at execution workspace, `git ls-remote --heads origin` for `lump/<lumpName>/*`); **lump-wide** across all discovery/scan lines (not per scan branch); limit reached → `skipped` variant; shared skips the cap (no `lump/…`); not duplicated in phase 1
