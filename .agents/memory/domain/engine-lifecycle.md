# Engine lifecycle

What `runLump` does per run and per context, failure reasons, history and transcripts, process spawning and killing.

- `executeStepsForContextList`: recursive/dynamic `steps` walk inline (each leaf: `promptFn` → `commandFn` → command → `postCommandExecFn` before next item)
- Per-context lifecycle: `branchFn` (once) → `setupWorkspaceFn` (once) → per context: `setupFn` → prompt loop → `teardownFn` → `gitCommitMessageFn` → `gitAddCommitFn` → finally `gitPushFn` (once) + `teardownWorkspaceFn` (once). After successful workspace setup, `teardownWorkspaceFn` always runs on any exit (step-walk failure/abort, git add+commit failure, throw, success); per-context `teardownFn` always runs after that context’s walk attempt (soft-fail: catch + `logger.error`, never blocks git / never becomes the returned Failure). On `stepWalkFailure` (incl. abort): skip git for that context, remaining contexts, and push; return `reason: 'stepWalkFailed'`. `gitAddCommitFn` Failure / `success('')` / throw / returned-command exec fail → hard-fail with `reason: 'gitAddCommitFailed'` (skip remaining contexts + push). Lone workspace-teardown command failure → `reason: 'workspaceTeardownFailed'` (if a step-walk / add+commit failure was already recorded, keep that reason). `gitPushFn` failures stay log-only. Success order: walk → `teardownFn` → add+commit → (other contexts) → push → workspace teardown. Git injectors return `MaybePromise<Success<Maybe<string>> | Failure<string>>` (`success(string)` → `execAsync` at `workspacePath`; nullish Success → no-op; empty string = failure)
- `contextRunState`: single plain object per context (`setupResult?.contextRunState ?? {}`); engine never freezes/clones/replaces it; command-module `setup` seeds at `<commandName>Setup`
- `PostCommandExecFn` gets `commandSucceeded: boolean` and `signal?: AbortSignal`; step-walk hooks (`StepFn` / `promptFn` / `commandFn` / `postCommandExecFn`) race via `awaitUnlessAborted` (throw-on-abort, single catch → `stepWalkFailed`); `Step.continueOnError` (default false) allows non-zero exit to continue; `CommandDescriptor.env` merges over `process.env`
- `collectStepsForContext` is plan-preview only (`planLumpFromJsConfig`); `*-on-copy` presets keep `projectRoot` as source repo and use an absolute copy path as branch `workspacePath`
- A `steps` item need not be an agent prompt: `promptTemplate`/`promptFn` are optional (omit → command runs with an empty prompt string); an inline `commandFn` returns `{ executable, args, env? }` (or `null` to skip) for plain shell/build/validation commands — the basis for verification/retry loops (`loop-example`, `getRecursiveSteps`)
- `runLump` calls `getToDoContextList` once before workspace setup; optional `refreshRemoteTrackingRefsFn` (CLI locked) runs once then status uses `skipFetch`; `getContextListFn` / status read source `projectRoot` (same as execution). Shared has no preflight. Refresh failure soft-falls to all-`toDo` for run/plan (warn); `buildContextStatusRecord` stays Failure
- `keepHistory: true` → `.lumpcode/lumps/<lumpName>/history/<contextName>.yaml`; `fs.mkdir` before initial `[]` write; `project-setup` gitignores `.lumpcode/**/history/` and `.lumpcode/.cache/`; append failures log `logger.warn` and do not abort the step walk; writes sanitize ANSI/C0 controls from `prompt`/`commandResult` (read-side recovery for corrupt files)
- `writeTranscripts` (CLI-only; lump > local > project; omit = on) gates daemon transcript files in `runLumpLine`; `false` skips `prepareLumpTranscriptFile` and leaves `liveStepWrite` unset. `lumpcode run` stdout is unchanged.
- Default branch prefix: `lump/${lumpName}/` (`LUMP_BRANCH_PREFIX`); custom naming via `branchFn` (CLI default: one context → `lump/<lumpName>/<contextName>`; multiple → sorted names + SHA-256, first 12 hex)
- Default git: `defaultGitAddCommitFn` (`git add . && git commit --allow-empty -m …`) + `defaultGitPushFn` (branch only, no tags); messages/branches wrapped with `shellSingleQuote`; only `gitCommitMessageFn` is a surfaced user knob (`LumpJsConfig` omits git injectors; CLI defaults via `getGitCommitMessage` + `makeGatedGitFns`)
- `execAsync`: optional `timeoutMillis`; Failure is `{ message, reason: 'timeout' | 'exit', info }` — timeout when Node's `exec` kill path fires (`killed` + configured `SIGTERM`; win32 `killed` only)
- `execBinary`: object API (`binaryPath`, `args`, optional `timeoutMillis`/`cwd`/`env`/`stdio`/`signal`/`killGraceMs`); `resolveSpawnExecutable` on Windows; npm/yarn `.cmd` shims for Node CLIs unwrap to `node <entry.js> …args` so multiline/backtick prompts are not mangled by `cmd.exe`/`%*` — Node is shim-dir `node.exe` else PATH `node` (never SEA/`process.execPath` unless basename is `node`, never a Node `.cmd` shim; bare `"node"` last resort so missing Node is ENOENT, not a silent cmd.exe wrap); same Node resolver for extensionless/shebang Node scripts; plain `.cmd`/`.bat` (no recognizable `.js` target) still wrap through `cmd.exe /d /s /c`; handles spawn `error` events for structured failures; resolves on spawn `'close'` (exit + stdio closed); on `timeoutMillis` or `AbortSignal`, tree-kills via `killProcessTree` (`killGraceMs` default 5000) then fails with `reason: 'timeout' | 'aborted'`; `RunLumpInput.signal` threads through `executeStepsForContextList` → `execBinary` and abort-raced hooks; abort ignores `continueOnError`; step walk spawns with `stdio: ['inherit', 'pipe', 'pipe']` so inherited stdin or lingering pipes (e.g. `npx` wrappers) can block completion after the inner command finishes
- Manual `lumpcode run` interrupt: `installRunAbortHandlers` — 1st Ctrl+C/`SIGTERM` aborts, 2nd force-exits (`130`), 5s grace then force-exit; sibling watchdog (same process group) SIGKILLs parent when a sync busy-loop blocks JS handlers; `runLumpFromJsConfig` registers `process.on('exit')` sync unlock (SIGKILL skips it → stale-PID recovery); dispose closes watchdog stdin
- Process kill helpers live in `@lumpcode/core`: `killProcessTree` (`graceMs` default 0 → immediate SIGKILL / taskkill `/T /F`), `isProcessAlive`, `nodeErrnoCode` — CLI imports from core (no local copies)
- `killProcessTree` (core; win32): `taskkill /T /F` can fail on SEA child trees ("operation not supported") — treat as success when the root PID is already gone (best-effort per PRD); `graceMs > 0` uses SIGTERM-then-SIGKILL on Unix
