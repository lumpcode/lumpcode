# Distribution

How the CLI is installed and packaged: npm, launcher, postinstall, SEA binaries.

- **Primary install**: `npm install -g @lumpcode/cli` (Node 22+); unscoped `lumpcode` meta package optional, not user-documented; `install.sh`/`install-local.sh` are optional channels — `--name` for alternate symlink when npm + standalone coexist
- Recipe-based JS/TS configs need resolvable `@lumpcode/recipes` and `@lumpcode/cli-utils` under the project (global CLI does not provide package resolution) — add them to the day-to-day repo's `package.json` before the first push so a dedicated clone's `npm install` gets them; non-JS repos use a minimal root `package.json` + `npm install`, or skip recipes and write plain `config.json`/`config.js`
- `bin/lumpcode.js`: native binary when present, else `node dist/index.js`; `--version` reads `package.json` via static import in `main.ts`; `clean` removes only SEA outputs under `bin/` (not the launcher); gitignore `packages/apps/cli/bin/*` with `!packages/apps/cli/bin/lumpcode.js` so SEA sidecars (`esbuild`, schemas, presets, platform binaries) stay untracked — same launcher-only track for `packages/apps/cli-meta/bin/lumpcode.js`
- `postinstall` reinstalls presets + downloads native binary to gitignored `vendor/` — skips in CI, monorepo dev (`src/root.ts` present), missing `dist/`, or `--ignore-scripts`; `LUMPCODE_SKIP_BINARY=1` skips binary only; `DEFAULT_INSTALL_REPO` in `native-binary.mjs` still `YOUR_ORG/Lumpcode` until wired to `lumpcode/lumpcode`
- SEA: minified `build:bundle` then format-only terser wrap (`max_line_len` 120) so uncaught errors do not dump a one-line bundle (`scripts/wrapMinifiedBundle.mjs`; skipped by `build:dev`); sidecars (`schemas/`, `presets/`, esbuild binary) beside `process.execPath`; `validateLumpJsonConfig` reads schema beside binary; embed static assets when feasible; macOS binaries ad-hoc codesigned only (strip quarantine xattr or sign + notarize for distribution)
- ncc emits CJS — use `lodash/camelCase` not `lodash-es`; `build:bundle` externalizes `esbuild`; SEA spawns esbuild sidecar via `execFile` (`esbuildPlatformBinaryRelativePath`: Windows `@esbuild/win32-x64/esbuild.exe`, Unix `bin/esbuild`)
