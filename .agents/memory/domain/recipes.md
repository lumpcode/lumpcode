# Recipes and kit

Behavior of `@lumpcode/recipes`: recipe factories, kit helpers, backlog item fields.

- Tasks: `name`, `task`, `priority` (lower = sooner), optional `dependsOn`, optional `workflow` array (`req` | `manualReq` | `testPlan` | `testImpl` | `impl` | `directImpl`), optional `manual`; `backlogItems/todo/<name>/requirements.md` and `testPlan.md` gate stages; item names must not end in `_req`, `_testPlan`, or `_testImpl`
- `@lumpcode/recipes` two layers: **recipes** (`backlog`, `featureBacklog`, `abstractionFinder`, `abstractionBacklog` — config from params) and **kit** (`src/kit/` — shared plumbing, barrel-exported; folder modules or single-file helpers); path-resolving recipes need lump `configUrl: import.meta.url` (derive lump dir via `fileURLToPath` + `lumpPathAndName` — never `path.join(import.meta.url, …)`); `defineRecipe`/`defineConfig` and engine hooks do not expose caller `lumpName` to recipe factories or `getContextListFn`; exported recipes/`defineRecipe` and variable-carrying kit (`retryUntilGreen`, `getRecursiveSteps`, …) must preserve caller dual generics `<V, SV>` with defaults (untyped `featureBacklog({…})` stays valid); context-list kit (`folderBacklogContexts`, `ephemeralContextListFn`) takes `<V>` only — not `SV`
- `backlog` recipe: typed stage map (`stages` + `resolveItem`); `resolveItem` receives concrete `discoveryBranch` from each context-list call (for per-scan staging/ignore); injects `TASK_NAME`, `TASK`, `BACKLOG_ITEMS_DIR`, `BACKLOG_ITEM_DIR`, `BACKLOG_STAGE`; `folderBacklogContexts` flattens `todo/<parent>/tickets/<ticket>/` as items (parent skipped by default when `tickets/` exists or `completed/<parent>/tickets/` has items; `includeUmbrellaParents` for featureBacklog wrap-up; names unique across top-level and tickets); `moveToDone` stages append `folderSetTaskDoneStep` (rename under `todo/` → the same relative path under `completed/`, including nested tickets; umbrella parent merges into existing `completed/<parent>/` when tickets are already there; then stamp `completedAt` on the completed `desc.yml`; `continueOnError: true` so move failures do not abort the lump); reserves `getContextListFn`/`steps`; optional project-root-relative `backlogItemsDir` override
- `featureBacklog`: requires `configUrl: import.meta.url`; optional `implValidateCommand`; optional `primaryDiscoveryBranch` (default `dev`) and `itemDiscoveryBranchPrefix` (default `feature`; neither may end with `/`; recipe emits `discoveryBranches: [primary, \`${prefix}/*\`]` and does not take `discoveryBranch`/`discoveryBranches`); optional `promptFns` overrides the main `promptFn` per stage (`req` | `testPlan` | `testImpl` | `impl` | `directImpl`; not `completion`; fix/validation prompts unchanged; defaults exported from `defaultPrompts.ts`; testImpl with no `testPlan` stage must not create `testPlan.md`); `desc.yml` `workflow` is an array of `req` | `manualReq` | `testPlan` | `testImpl` | `impl` | `directImpl` (omit ≡ `[req, testPlan, testImpl]`; ticket omit inherits parent; `ENOENT` parent → same default; order ignored, canonicalized; duplicates/unknown/string throw; `req`+`manualReq` keeps `manualReq` (warn once); `impl`+`directImpl` keeps `directImpl`; neither terminal → `impl`); `req` is the agent requirements context; `manualReq` is a gate (no context) that waits for `requirements.md`; `directImpl` may implement without `requirements.md`; default `impl` waits for that file unless `req` is in the array; `manual: true` ignores standalone/tickets after umbrella `completion` (not inherited); desc.yml field `manualReq` (boolean) is ignored with a once-per-process warn; context names `<name>_req` / `_testPlan` / `_testImpl` then unsuffixed `<name>` (`impl`/`directImpl`/`completion`); `testImpl` marks new/updated cases `it.skip`/`describe.skip`; artifact stages use `retryUntilGreen` + `requireArtifactStep`; tickets at `todo/<parent>/tickets/<ticket>/` (parent never runs item stages; after all tickets finish, one `completion` parent context depends on every `<parent>-<ticket>` impl name and merges parent into `completed/`; ticket `dependsOn` prefixed the same way); discovery: primary → top-level items without `testPlan`/`testImpl` (tickets never); `<prefix>/<key>` → exact item or parent; `getContextStatus` uses the concrete `discoveryBranch`
- `retryUntilGreen`: kit wrapper over `getRecursiveSteps` — iteration 0 runs `steps`, retries run optional `fixSteps` resolver (`GetFirstStepsInput` → steps) or default fix prompt (formatted `prevValidateCommandDescriptor` + output); `validationCommandFn` required; barrel-exported; `abstractionBacklog` and `featureBacklog` use it; recursion returns next iteration steps from validation `postCommandExecFn` (not a trailing `StepFn` + run-state flag)
- `requireArtifactStep`: returns a `ValidationCommandFn` that exits 0 when the context-var path exists, else exits 1 with an error message (missing variable still throws)
- `openPrPostTeardown`: `{ provider: 'github' }` → `postTeardownWorkspaceFn`; opens a PR from `branchName` into resolved `baseBranch` via `execBinary` (`gh`/`git` on PATH, argv not shell) after push; default title `LUMP: <lumpName> - <contexts>` (lump name from `lump/<lumpName>/…` or `lumpName` option); skip if head is missing on origin or a PR already exists; create failures log-only (never `workspaceTeardownFailed`). Wired on `backlog`, `docs`, `qol`, `bugfixes`, `abstractionFinder`, `abstractionImplementer`, and `presetSmoke`
- `backlogItems/` folder layout is for backlog-style recipes only (`backlog`, `featureBacklog`, `abstractionBacklog` / implementer lumps) — not every lump; future recipes may omit it
- `abstractionFinder` + `abstractionBacklog` (two-lump CLI-util pipeline): finder requires `configUrl` + implementer `backlogItemsDir` (no `implementerLumpName` recipe default; finder does **not** own a `backlogItems/` tree); `maxPendingAbstractions` caps `todo/` item count via `listTodoRelativeDirs` and emits **one** ephemeral context per tick while under the cap (empty list when at/over cap); optional `scanCommand` prepends a scanner step; default prompt uses `scanDirectories` / optional `utilDir` (not a hardcoded CLI path); caller `steps` replace the default prompt; implementer delegates to generic `backlog` with single `implementation` stage (items without `requirements.md` skipped); kit (`validateBaseBacklogItem`, `resolveBacklogPaths`, `folderBacklogContexts`, `listTodoRelativeDirs`, `folderSetTaskDoneStep`, `getRecursiveSteps`, `retryUntilGreen`, `requireArtifactStep`, `shellCommand`, `resolveImplValidateCommand`, `openPrPostTeardown`; deprecated `ymlBacklogContexts`/`setTaskDoneStep` warn once); `getRecursiveSteps` `ValidationCommandFn` is `MaybePromise<CommandDescriptor | null | undefined>`; `.lumpcode/lumps/abstractionFinder/` + `abstractionImplementer/` use abstraction recipes
