# Daemon

Scheduler identity, start/stop/restart, supervisor, desired.json, ticks, daemon files.

- One daemon model: every `start` discovers like today’s former global (dedicated: all primary-branch subticks), then applies optional `--include` / `--exclude` (`*` globs). Identity is **`daemonId`** (`~/.lumpcode/daemons/<project>.<daemonId>.daemon.*`); default unfiltered id `global` (reserved for unfiltered). Overlapping filtered daemons allowed (unique id); start gates on unique id + corrupt-meta fail-closed only. Multiple `--include` daemons on one dedicated clone under **worktree** are supported: path locks + **git-common-dir lock** (path then git order); worktree releases the execution-path lock after setup fn returns (not via `afterExec` when setup `command` is empty). CLI gates setup/teardown/add+commit/push under that lock via `makeGatedGitFns` (`gitAddCommitFn` / `gitPushFn` return Result; nullish Success = already done). Context status uses one locked `refreshRemoteTrackingRefs` (`git fetch --prune --no-write-fetch-head origin`) then `getContextStatus({ skipFetch: true })` — injected on `RunLumpInput` / `getToDoContextList`; CLI `getContextStatus` / `getContextStatuses` / `lump-plan` / `buildContextStatusRecord` take the same lock (`lockMode: 'wait'`)
- Auto-id: single exact include → that name (`name-2`…); multi/glob → `d-` + 6 hex; `--daemonId=global` with any filter fails. Deprecated `--lumpName` on start ≡ `--include=<name>` (warn); on companions ≡ `--daemonId`
- `start` detaches by default; companions: `stop`, `restart`, `daemon-log`, `daemon-status` (`--daemonId`, default `global`), `supervise --foreground`. `daemon-status` with no id flags **lists all** project daemons and adds `supervisor: { running, pid? }`. Supervisor files: `~/.lumpcode/supervisor/<projectName>.{pid,log,meta.json}` (not a daemon id, not under `daemons/`)
- `start` writes `~/.lumpcode/daemons/<project>.<id>.daemon.desired.json` before spawn (`projectRoot`, `daemonId`, `cronSetup`, optional include/exclude/maxParallelRun; no `--json`/`--verbose`). In-memory spec is **`StartDaemonRecipe`** in `startDaemonDesired` (`recipeFromDesired` is the only Recipe constructor; `fromMeta` / `toDesired` / `toMetaWrite` / `toForegroundArgs`; desired is `Omit<recipe, 'workspaceStrategy'>` plus optional `stopping`). Detached parent claims the PID file via `spawnDetachedLumpcodeWithPidFile` (`wx` + kill-on-fail + stub meta). `start` and `restart` share **`launchStartDaemon`** (util; explicit `Success<LaunchStartDaemonOutput> | Failure<LaunchStartDaemonFailure>`). `restart` snapshots **desired.json** then **`stopOneDaemon`** then launch (`fromMeta` only as legacy adopt). No snapshot (missing desired and unreadable meta): live pid → fail closed without stop; stale pid → **`unlinkBestEffort`** leftovers (same stale message as stop); missing pid → same missing message as stop — never invent a default recipe or run operator-stop just for messaging. `stop` / `restart` map operator stop results via **`stopOneDaemonCliFailure`**. `start` starts `supervise --foreground` if that project's supervisor PID is dead. Tests inject `skipEnsureSupervisor`
- Desired `stopping: true` = operator drain (idle `stop` / Ctrl+C / SIGTERM / `stop --all` / `--force`). Unlink desired **after** the process is confirmed dead so supervise cannot respawn mid-kill. OOM/`kill -9` leaves desired so supervise respawns. Busy single `stop`/`restart` still refuse `daemonBusy` and leave desired unchanged
- Supervise keep-alive (`runSuperviseLocalPass`, ~30s) rebuilds the spawn recipe from **that daemon id’s meta** `workspaceStrategy`, not a live `local.json` read (checkout+worktree mix on one clone is unsafe). Strategy is per id (siblings may differ; `lumpcode start` still reads live `local.json`). Missing or invalid meta skips spawn (fail-closed); leftover `desired.json` stays until a fresh `start`. Keep-alive is desired.json vs live PIDs only — repo `.lumpcode/daemons/` recipes are a separate reconcile (`discoverDaemonConfigFiles` via `git ls-tree`; `reconcileDaemonConfigFiles` under git-common-dir lock after fetch). File reconcile **starts** enabled missing daemons and **stops** daemons whose file was deleted or `disabled` (files are the machine inventory); it does not restart a stopped file daemon (`desired.json` from that start owns keep-alive restart). Busy stop stays due (retry next ~30s keep-alive); other start/stop outcomes advance the 5-minute reconcile clock
- `stop --all` is project-scoped: mark all desired stopping first, drain/kill lump daemons, delete leftovers, then stop supervise. Only `stop --all` stops supervise (no `supervise-start` / `supervisor-stop`)
- PID/meta JSON for the scheduler is written by the **foreground** child (detached parent also writes a stub). Meta writes `daemonId`, `include`/`exclude`, optional `maxParallelRun`; never writes `lumpName` (read-only compat). Desired.json is source of truth; live pid with no desired is adopted as legacy
- Croner `{ protect: true }` + `await runTick()` (ticks do not overlap); worktree concurrency = `--maxParallelRun` ?? `local.json.maxParallelRun` ?? `1` (checkout always `1`; CLI flag with checkout fails) — caps concurrent **lump lines** in one tick via `runLumpLinesWithConcurrency`, not contexts inside one lump (`numberOfContextsPerBranch` still sequential on one branch)
- **`discoverLumpNames`** / **`discoverLoadableLumps`** / **`discoverLoadableLumpNames`**: all lump dirs vs single-pass loadable `{ lumpName, jsConfig }[]` (optional `logger` warns invalid dirs); names-only wrapper — used by `start`, `validateDaemonLaunch`, `resolveTargetLumpNames`, `lump-status`, `discoverDedicatedLumpsForScanBranch`
- **`discoverDedicatedLumpsForScanBranch`**: dedicated discovery helper — locked preflight to `scanBranch`, then `discoverLoadableLumps`, then filter by `resolvedDiscoveryBranch`; optional `afterMatched` runs in-lock after filter, before path-lock release (tick: parallel `snapshotDedicatedLumpLine` while checkout is still `scanBranch`); used by daemon tick and `validateDaemonLaunch`
- **`validateDaemonLaunch`**: filesystem-only at start for every daemon (allowlist, duplicate-name); dedicated locked preflight per `primaryBranches`; dirs without config → `logger.warn` and skip; fail-fast on same-primary duplicate `lumpName`, unlisted discovery branch, discovery preflight failure
- Tick (dedicated): `collectDedicatedTickLumpLines` in `runForeground.ts` owns dedicated collect; per primary-branch subtick → locked discover (in-lock `snapshotDedicatedLumpLine` for **every** matched lump via `afterMatched` — `Promise.all` while checkout is still `scanBranch`; fail-closes if `projectRoot` HEAD ≠ `effectiveDiscoveryBranch` because `getCodeBasePaths` is a working-tree walk) → include/exclude → path-lock release → `scoreDedicatedLumpLineSnapshots` (one locked remote refresh per scan branch; success → no-op refresh; failure injects the same Failure so status soft-falls to all-`toDo`; per line, `scoreDedicatedLumpLine` classifies the frozen snapshot context list via core `getToDoContextList` with an injected `getContextListFn: async () => snapshot.contextList`) → `reorderDedicatedLumpLines` directly (slot-stable, so single-line lumps are an identity transform; failed lines warn and stay in slot) → run or no-op; pass `effectiveDiscoveryBranch` into `runLumpFromLumpName`. Tick identity is **`LumpLine`** (`lumpName` + optional `effectiveDiscoveryBranch`; omitted = shared collect, no discovery bind); dedicated scoring/reorder use **`DedicatedLumpLine`** (branch required). `scoreDedicatedLumpLine` owns `LineScore` / `ScoredLumpLine` (`DedicatedLumpLine` + score; scored `values[]` are every `numberOfContextsPerBranch`-th sorted eligible-todo priority, not a scalar min; ready snapshot carries that count from `RunLumpInput`); `reorderDedicatedLumpLines` fills each lump's non-failed collect rows from the merged batch stream (same line may repeat; unused leftovers are unused lines, scored before empty); `collectTickLumpLines` returns `LumpLine[]`; pool is `runLumpLinesWithConcurrency` (same `lumpName` + `effectiveDiscoveryBranch` never overlap). Tick public surface is `snapshotDedicatedLumpLine` + `scoreDedicatedLumpLine` + `scoreDedicatedLumpLineSnapshots` (batch wrapper sharing one refresh per scan branch). Cap stays lump-wide (`evaluateTooManyOpenBranchesSkip`); context `priority` still sorts todos inside one `runLump`. Shared collect: no score/reorder. No `ignoredByGlobalDaemon` (removed)
- Manual `run`: no daemon PID gate — coordinates via workspace locks only (`lockMode: 'fail'` vs daemon `wait`); dedicated `dedicatedRestoreBranch` `git switch` in handler `finally` after lock release
- Default `stop` refuses when mid-run (`isDaemonMidRun` / `daemonBusy`) or when meta is missing/invalid (`daemonMetaCorrupt`); idle SIGTERM waits **`DAEMON_IDLE_STOP_WAIT_MS` (5s)** then **`stopOneDaemon`** (result cannot be `draining`). `--force` tree-kills with `graceMs: 0` and does **not** require readable meta. `stop --all` marks all desired stopping, then loops **`drainOrStopOneDaemon`** (mid-run → `draining`; corrupt meta proceeds; result cannot be `busy` / `metaCorrupt`), polls leftovers, unlinks, then **`stopSupervisor`** (pid + supervisor meta only; never `readDaemonMeta` / desired.json). Desired ids: `listDaemonIds({ kind: 'desired' })`. Path bundle: **`daemonSchedulerFiles`** owns modern paths, **`legacyGlobalDaemonSchedulerFiles`**, and **`unlinkSchedulerFiles`**. Supervisor / generic unlinks use **`unlinkBestEffort`**. `RunningDaemonInfo` is the file bundle plus `pid` and either `{ meta: DaemonMeta }` or `{ metaStatus: 'missing' | 'invalid' }` (`hasRunningDaemonMeta`). PID claim: `claimPidAndWriteMeta` (exclusive `wx` is private). Cleanup: `unlinkSchedulerFiles` (path bundle) / `unlinkBestEffort` / `removeOwnPidArtifacts` (`claimPidAndWriteMeta`). `installProcessShutdown` runs `onSignal` for OS signals, `shutdown()`, and `waitForShutdownOverride`.
- `readDaemonMeta` fails closed (`missing` / `invalid` / `io`) — never invent checkout/idle from a missing file; valid meta may still default omitted `workspaceStrategy` to `checkout`
- Alive PID + bad meta: `listRunningProjectDaemons` returns `{ metaStatus: 'missing'|'invalid' }` keyed by `daemonId` (legacy bare `<project>.daemon.pid` maps to `global`); `assertDaemonStartAllowed` / `start` refuse with `daemonMetaCorrupt`; `restart` snapshots desired.json (legacy: meta) then `stop --force` when meta is unreadable
- Foreground daemon arms native SIGINT/SIGTERM via **`installProcessShutdown`** (shared with supervise; drain calls `shutdown()`) **before** the first `runTick`, plus `installDaemonProcessGuards` (ignore SIGHUP with one log line — `stop` stays SIGTERM; `uncaughtException` / `unhandledRejection` log + `exit(1)` — lump command Failures stay in the Result path; blocking stdout/stderr); in-flight meta writer keeps in-memory `inFlightRuns` and writes `baseMeta` plus live overlay (no `inFlightLumpCount`; no read-merge); `busy` is deprecated read-only; `isDaemonMidRun` uses `inFlightRuns.length` with read fallback to legacy count/`busy`
- `daemon-log`: follows by default; `--noFollow` prints and exits; `--lines` limits initial output; daemon/supervisor logs are append-only (`~/.lumpcode/daemons/<project>.<id>.daemon.log`); `local.json` `logRetention.maxAgeDays` (omit = 14, `0` = keep) trims them in place and deletes old transcript/history files on `run` and each daemon tick (`retainLumpcodeLogs`); lump `verbose` dumps full agent stdout; `stop --all` unlinks scheduler logs as teardown
- Cross-lump `dependsOnContexts`: warns when `otherLump.baseBranch !== thisLump.baseBranch`
- Treat `.lumpcode/` configs and command modules as trusted executable code
