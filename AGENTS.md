## Learned User Preferences

### Code style

- Type functions with a direct `function` declaration or arrow functions; avoid `<Type>function` casts and the `const name = function name(...)` pattern
- Prefer a single destructured object argument for functions with 3+ parameters
- One type per file in `packages/core/src/types/`; types defined independently from default implementations
- Return `Success<T>` / `Failure<string>` for expected failures (`success()` / `failure()` from `@lumpcode/core`); resolve costly dynamic `import()` eagerly at configuration time, not during execution
- Use `cwd` with `execAsync`/`child_process` instead of `cd ... &&`; command functions return only the command string, pass `cwd` at the call site
- Limit change scope to specified packages; note follow-up work for other packages separately
- `@lumpcode/recipes` kit: reuse `@lumpcode/core` and exported `@lumpcode/cli-utils` helpers (`normalizeSteps`, `readYamlList`, …); lift CLI-only shared utils into `cli-utils` rather than duplicating in recipes — async-only when sync wrappers add no call-site value; recipe step types use CLI `LumpJsConfigSteps`, not core `Steps`; multi-file kit utils live under `src/kit/<name>/{main.ts,index.ts,unit.test.ts}` (single-file `src/kit/<name>.ts` OK for small helpers); barrel-export from `kit/index.ts`; do not invest in sharing implementations with deprecated `ymlBacklogContexts`/`setTaskDoneStep`
- CLI utils live flat under `packages/apps/cli/src/utils/` (one util per directory: `main.ts` + `index.ts`, barrel-exported from `utils/index.ts` — no nested subdirs). Shared test-only helpers go under `packages/apps/cli/src/testing/` with a barrel `index.ts`. Prefer a private inline helper in the calling module over a new util directory for small single-caller logic. Command modules must not import other command `main` modules (tests may import commands as fixtures); two-caller command logic belongs in a util with an explicit `Success`/`Failure` type, not `ReturnType<CommandHandlerMaker<…>>`
- Name path-lock release callbacks `releaseLock`, not phase-specific names (e.g. `phase1Lock`); enforce each guard/skip at one canonical layer — do not duplicate the same check in both `runLumpFromLumpName` and `runLumpFromJsConfig`

### Testing

- Prefer integration tests with real fixtures over mocking; test behavior, not implementation; avoid unnecessary dependency injection (mock the underlying API instead); do not inject TTY detection unless there is a strong reason; when extending coverage, prefer updating/augmenting existing tests over wholly new cases when substantive candidates exist
- Temp git repos: set local `user.name`/`user.email` before `git commit` (CI runners lack global identity)
- File writes: use the temp `projectRoot`/`tmpDir`, not process `cwd`, so teardown removes them
- TS transpile tests: assert `.lumpcode/.cache/transpile/` cache hits (`readCacheMeta` in `tsLumpFixtures.ts`) — Node 22 Vitest can natively import temp `.ts`, which false-greens `resolveImportable` tests before esbuild wiring; Vitest aliases `esbuild` to `src/testing/esbuildVitestShim.ts`
- Not-yet-implemented utils: add index-barrel-exported stubs (throwing `not implemented`) plus the types tests import so tests compile and run red until implementation lands; backlog `testImpl` / tests-only work keeps future suites skipped and must not change production code to green them — unskip during the implementation stage
- Core process-tree unit tests share `packages/core/src/testing/processTreeTestHelpers.ts` (`probeAlive`, `waitForPidGone`, `waitForReadyFile`) — reuse across `killProcessTree` / `execBinary` / timeout-abort suites instead of duplicating wait helpers
- Large helper/command suites may colocate under `<name>/testing/` (first: `executeStepsForContextList/testing/`, CLI: `commands/start/testing/`, `utils/jsConfigToRunLumpInput/testing/` — `general.unit.test.ts`, topic files, `testHelpers.ts`); keep `main.ts`/`index.ts` at the module root; exclude `**/helpers/**/testing/**` (core) and `**/commands/**/testing/**` + `**/utils/**/testing/**` (CLI) from package tsconfig emit
- Backlog `testPlan.md` locations (`**Where:**`, host tables) cite package-rooted paths (e.g. `packages/core/src/helpers/<name>/testing/general.unit.test.ts`), not bare `unit.test.ts`

- `AGENTS.md` continual-learning: capture durable principles and workspace facts, not session change logs or verbatim grilling Q&A outcomes

### CLI conventions

- Unregistered `login`/`logout` command modules are **implementation-only** — do not document in user-facing README/DOCS (`npm login` in `DOCS/publishing.md` is npm registry auth only). `supervise` is the same: `start` launches it; do not tell operators to run it; project-wide stop is `stop --all`
- Arguments before options in usage; long option names in camelCase (e.g. `--lumpName`, `--contextName`, `--lines`) to match Commander/schema — avoid single-char keys needing special `addCommand` handling
- Lump-config `command` field: registered tag (`"copilot"`, `"cursor"`, …) **or** lump-relative `.ts`/`.js` path (no whitespace; same `CommandModule` exports as `commands/<name>`); never shell flags — agent flags belong in the module's `CommandFn` (`executable` + `args`)
- Lump configs: omit CLI-default fields (`numberOfContextsPerBranch: 1`, `verbose`/`keepHistory` off); keep only intentional overrides
- Omit boolean flags for defaults; pass once for the non-default — no `--<name> true|false` or legacy two-token boolean argv

### npm publish

- Publishable `package.json` files: include `repository` (link to `lumpcode/lumpcode`) and relevant `keywords`
- Version/publish scripts (`scripts/set-npm-versions.mjs`, `scripts/publish-npm.mjs`) share catalog `scripts/npm-packages.mjs` (ids: `core`, `cli-types`, `cli-utils`, `recipes`, `cli`, `lumpcode`); `--packages` selects a subset (omit = all); `--ignore-packages` excludes ids after that selection (same aliases/forms; errors if selection empties); selective bumps only rewrite internal `@lumpcode/*` deps when both ends are in the selection; version early-exit must compare every selected package, not only `core`
- `@lumpcode/cli` `files` must ship the full postinstall chain (`scripts/esbuild-sidecar.mjs`, `scripts/native-binary.mjs`, `scripts/postinstall.mjs`)
- Before publish: smoke-test the packed tarball (`npm pack --dry-run | rg scripts/`, extract, `import './scripts/native-binary.mjs'`, `LUMPCODE_SKIP_BINARY=1 node scripts/postinstall.mjs`)
- Release PRs to `main`: use merge commit, not rebase merge — rebase rewrites SHAs so the release branch is not an ancestor of `main` (identical tree, phantom follow-up PR)
- Prefer a single root `package.json` script per tool; forward flags with `npm run <script> -- --flag` instead of one wrapper script per flag

### Core domain model

- **Project**, **Lump**, **Context**, **Steps** (recursive), **Recipe**
- Context status from commit messages on remote refs (`gitCommitMessageFn`; default core: `LUMP:${context.name}`; CLI: `getGitCommitMessage({ contextName, lumpName })`): `toDo` → `branchPushed` → `finished` (remote is source of truth). Match with core `commitMessageIncludesMarker` (string anywhere in full `%B`, end bound so `foo` ≠ `foo-bar`); log format `GIT_LOG_HASH_BODY_FORMAT` (`%x1e%H%x00%B`) via `parseGitLogHashBodyRecords`. Same matcher for `clean --contextName`; CLI `buildContextStatusRecord` discovers names via `contextNamesAfterLumpPrefix`. Lumpcode still writes a one-line marker subject. Marker strings in git history are the only SoT — do not add a committed JSON (or other) status overlay; operators keep LUMP marker strings when squashing
- `getToDoContextList` validates names via `validateContextListNames` (unique, `^[a-zA-Z0-9_-]+$`); resolves status via `contextStatusMap.get(context.name)` (not parallel-list index) because `dependsOnContexts` can insert names absent from `contextList`
- Cross-lump `dependsOnContexts`: composite `lumpName/contextName`; CLI `makeGitCommitMessageFnFromLumpName` maps `/` in dependency refs to `LUMP:<referencedLump> - <contextName>` — slash only for dependency refs, not same-lump context names
- Lump config precedence: **`config.ts` > `config.js` > `config.json`**; hook `*Fn` paths and custom commands support **`.ts`**; shipped presets stay **`.js`** only; `lump-create` scaffolds JSON/JS only
- Per-lump `disabled`: boolean, zero-arg sync/async fn, or `FilePath` to a module — phase 1 returns `{ skipped: true, reason: 'disabled' }` (exit 0 on manual `run`); daemon `runTick` logs info and continues; no `enable`/`disable` subcommands

### Context sourcing (mutually exclusive)

- `contextListJson` (static JSON), `getContextListFn` (dynamic), or `contextMatchFn` (file scanner)
- `contextMatchFn`: each call gets `codeBasePath`, full `codeBasePaths`, `lumpVariables`; same `contextName` merges (variables accumulate; later match wins duplicate keys/`contextOptions`)
- CLI `GetContextListFnInput`: `codeBasePaths` + `lumpVariables` + concrete `discoveryBranch` (core omits discovery; CLI adapts at the run boundary) — no `projectRoot`/`baseBranch`; daemon/CLI discovery matching selects lumps only — per-branch context filtering belongs in the author's `getContextListFn` / recipe `resolveItem`

### Engine execution

- `executeStepsForContextList`: recursive/dynamic `steps` walk inline (each leaf: `promptFn` → `commandFn` → command → `postCommandExecFn` before next item)
- Per-context lifecycle: `branchFn` (once) → `setupWorkspaceFn` (once) → per context: `setupFn` → prompt loop → `teardownFn` → `gitCommitMessageFn` → `gitAddCommitFn` → finally `gitPushFn` (once) + `teardownWorkspaceFn` (once). After successful workspace setup, `teardownWorkspaceFn` always runs on any exit (step-walk failure/abort, git add+commit failure, throw, success); per-context `teardownFn` always runs after that context’s walk attempt (soft-fail: catch + `logger.error`, never blocks git / never becomes the returned Failure). On `stepWalkFailure` (incl. abort): skip git for that context, remaining contexts, and push; return `reason: 'stepWalkFailed'`. `gitAddCommitFn` Failure / `success('')` / throw / returned-command exec fail → hard-fail with `reason: 'gitAddCommitFailed'` (skip remaining contexts + push). Lone workspace-teardown command failure → `reason: 'workspaceTeardownFailed'` (if a step-walk / add+commit failure was already recorded, keep that reason). `gitPushFn` failures stay log-only. Success order: walk → `teardownFn` → add+commit → (other contexts) → push → workspace teardown. Git injectors return `MaybePromise<Success<Maybe<string>> | Failure<string>>` (`success(string)` → `execAsync` at `workspacePath`; nullish Success → no-op; empty string = failure)
- `contextRunState`: single plain object per context (`setupResult?.contextRunState ?? {}`); engine never freezes/clones/replaces it; command-module `setup` seeds at `<commandName>Setup`
- `PostCommandExecFn` gets `commandSucceeded: boolean` and `signal?: AbortSignal`; step-walk hooks (`StepFn` / `promptFn` / `commandFn` / `postCommandExecFn`) race via `awaitUnlessAborted` (throw-on-abort, single catch → `stepWalkFailed`); `Step.continueOnError` (default false) allows non-zero exit to continue; `CommandDescriptor.env` merges over `process.env`
- `collectStepsForContext` is plan-preview only (`planLumpFromJsConfig`); `*-on-copy` presets keep `projectRoot` as source repo and use an absolute copy path as branch `workspacePath`
- A `steps` item need not be an agent prompt: `promptTemplate`/`promptFn` are optional (omit → command runs with an empty prompt string); an inline `commandFn` returns `{ executable, args, env? }` (or `null` to skip) for plain shell/build/validation commands — the basis for verification/retry loops (`loop-example`, `getRecursiveSteps`)
- `runLump` calls `getToDoContextList` once before workspace setup; optional `refreshRemoteTrackingRefsFn` (CLI locked) runs once then status uses `skipFetch`; `getContextListFn` / status read source `projectRoot` before `setupWorkspaceFn` switches branch — shared mode pre-flight never touches source. Refresh failure soft-falls to all-`toDo` for run/plan (warn); `buildContextStatusRecord` stays Failure
- `keepHistory: true` → `.lumpcode/lumps/<lumpName>/history/<contextName>.yaml`; `fs.mkdir` before initial `[]` write; `project-setup` gitignores `.lumpcode/**/history/` and `.lumpcode/.cache/`; append failures log `logger.warn` and do not abort the step walk; writes sanitize ANSI/C0 controls from `prompt`/`commandResult` (read-side recovery for corrupt files)
- Default branch prefix: `lump/${lumpName}/` (`LUMP_BRANCH_PREFIX`); custom naming via `branchFn` (CLI default: one context → `lump/<lumpName>/<contextName>`; multiple → sorted names + SHA-256, first 12 hex)
- Default git: `defaultGitAddCommitFn` (`git add . && git commit --allow-empty -m …`) + `defaultGitPushFn` (branch only, no tags); messages/branches wrapped with `shellSingleQuote`; only `gitCommitMessageFn` is a surfaced user knob (`LumpJsConfig` omits git injectors; CLI defaults via `getGitCommitMessage` + `makeGatedGitFns`)
- `execAsync`: optional `timeoutMillis`; Failure is `{ message, reason: 'timeout' | 'exit', info }` — timeout when Node's `exec` kill path fires (`killed` + configured `SIGTERM`; win32 `killed` only)
- `execBinary`: object API (`binaryPath`, `args`, optional `timeoutMillis`/`cwd`/`env`/`stdio`/`signal`/`killGraceMs`); `resolveSpawnExecutable` on Windows; npm/yarn `.cmd` shims for Node CLIs unwrap to `node <entry.js> …args` so multiline/backtick prompts are not mangled by `cmd.exe`/`%*` — Node is shim-dir `node.exe` else PATH `node` (never SEA/`process.execPath` unless basename is `node`, never a Node `.cmd` shim; bare `"node"` last resort so missing Node is ENOENT, not a silent cmd.exe wrap); same Node resolver for extensionless/shebang Node scripts; plain `.cmd`/`.bat` (no recognizable `.js` target) still wrap through `cmd.exe /d /s /c`; handles spawn `error` events for structured failures; resolves on spawn `'close'` (exit + stdio closed); on `timeoutMillis` or `AbortSignal`, tree-kills via `killProcessTree` (`killGraceMs` default 5000) then fails with `reason: 'timeout' | 'aborted'`; `RunLumpInput.signal` threads through `executeStepsForContextList` → `execBinary` and abort-raced hooks; abort ignores `continueOnError`; step walk spawns with `stdio: ['inherit', 'pipe', 'pipe']` so inherited stdin or lingering pipes (e.g. `npx` wrappers) can block completion after the inner command finishes
- Manual `lumpcode run` interrupt: `installRunAbortHandlers` — 1st Ctrl+C/`SIGTERM` aborts, 2nd force-exits (`130`), 5s grace then force-exit; sibling watchdog (same process group) SIGKILLs parent when a sync busy-loop blocks JS handlers; `runLumpFromJsConfig` registers `process.on('exit')` sync unlock (SIGKILL skips it → stale-PID recovery); dispose closes watchdog stdin
- Process kill helpers live in `@lumpcode/core`: `killProcessTree` (`graceMs` default 0 → immediate SIGKILL / taskkill `/T /F`), `isProcessAlive`, `nodeErrnoCode` — CLI imports from core (no local copies)

### CLI project config

- Project root: directory with both `.lumpcode` and `.git`; engine `projectRoot` = parent of `.lumpcode/` (`jsConfigToRunLumpInput` derives from `localConfigFolderPath`)
- **`project.json`**: `projectName` (letters, digits, `_`, `-` only); inferred from `git remote get-url origin` or sanitized basename on `project-setup`; used for daemon filenames and `project-copies/<projectName>/`
- **`.lumpcode/local.json`** (gitignored; scaffolded by `project-setup --mode`): **required** for `run`/`start` — `mode` (`shared` | `dedicated`), `primaryBranch` or `primaryBranches`, optional deprecated `projectBaseBranch` alias (warn once via `resolvePrimaryBranches` when logger passed), optional `workspaceStrategy` (`checkout` | `worktree`, default `checkout`), optional `disabled` (boolean — daemon skips all lumps on machine; manual `run` unaffected), optional `maxParallelRun` (positive int; default `1` — global-daemon concurrency only when `workspaceStrategy` is `worktree`; checkout warns once and stays sequential). No `--mode`/`--force` on `run`/`start` — edit `local.json`. Read once at daemon startup (restart to pick up changes). When the repo integrates on `dev`, set `primaryBranch`/`primaryBranches` to `dev` so lump branches and context status track the integration branch

### Branch resolution (v0.0.9)

- Split **execution** (`baseBranch`) from **discovery** (`discoveryBranch` / `discoveryBranches`, mutually exclusive; exact and/or git refname globs); design ref: `.lumpcode/lumps/v0.0.9/multi-project-base-branches.reference.md`
- `effectivePrimaryBranches` = non-empty `primaryBranches` else `[primaryBranch]` (exact + glob strings; unexpanded); resolved `primaryBranch` = first **exact** entry (`resolvePrimaryBranch` — all-glob list throws)
- `resolvedDiscoveryBranch` = concrete discovery (CLI `--discoveryBranch`, else first exact discovery rule, else `primaryBranch`); pattern-only `discoveryBranch(es)` require `--discoveryBranch` for manual `run`/`lump-plan`/`lump-status`
- `resolvedBaseBranch` = lump `baseBranch ??` concrete discovery `?? primaryBranch`
- `resolvedBaseBranch` on `RunLumpInput` drives context status and worktree fetch; pre-flight/teardown use `resolvedBaseBranch`
- **Dedicated allowlist**: each discovery rule must be allowlisted against configured (unexpanded) `effectivePrimaryBranches` — enforce in **`runLumpFromJsConfig`** and explicit `--lumpName` daemon launch (`validateLumpDiscoveryBranchAllowlist`); redundant in dedicated global **`validateDaemonLaunch`** loop after `discoverDedicatedLumpsForScanBranch` (helper filters by scan branch); not `baseBranch`; command handlers must not duplicate
- **Shared mode**: no allowlist; lump `discoveryBranch`/`discoveryBranches` and `--discoveryBranch` ignored for `run`/daemon scheduling; `lump-plan`/`lump-status` honor concrete `--discoveryBranch` for inspect-only context filtering (no checkout); multi-`primaryBranches` logs once (dedicated-only feature); executes on copy at `resolvedBaseBranch`, discovers from source `projectRoot`
- Dedicated daemon tick: `expandPrimaryBranches` → concrete `scanBranches` (configured-entry expand, then the resolved primary / first exact is moved to index 0; remaining branches keep expand order; shared mode does not expand globs); same `lumpName` on different primary branches OK; duplicate `lumpName` on same primary-branch scan fails launch
- Dedicated discovery `refreshCommand`: optional non-empty shell string on merged `project.json` / `local.json` (local wins, frozen at `start`); tick passes it into `discoverDedicatedLumpsForScanBranch` after preflight and before config load (`execBinary` shell wrapper, `stdio: 'ignore'`, `REFRESH_COMMAND_TIMEOUT_MS` 15 min); `validateDaemonLaunch` and manual `run` omit it; failure skips that scan branch only
- `lump-plan`/`lump-status`: non-destructive (no pre-flight); manual `run` requires lump config on current checkout

### Workspaces and pre-flight

- **Execution workspace** (`executionWorkspacePath`): project copy in `shared`, operator checkout in `dedicated`
- **Branch workspace**: mapped to core `workspacePath` via `makeLumpWorkspaceFns` → `setupWorkspaceFn` (checkout or worktree; not `runProjectPreflight`); worktrees at `.lumpcode/worktrees/<branch-as-nested-dirs>/` under execution workspace (CLI-only; engine `cwd` stays source `projectRoot`)
- Checkout strategy: `atDirectory(executionWorkspacePath, …)` (`cd /d` on win32). Worktree strategy: `git -C <executionWorkspacePath>`, `shellSingleQuote` on slash branch names, `shellBestEffort` for best-effort steps, platform-specific rm, `mkdir` worktree parent before `git worktree add` on Windows
- **`runProjectPreflight` / `runPreflight`**: execution-workspace only — `git fetch --no-write-fetch-head origin <branch>` / switch / hard-reset (no pull); fetch/switch/reset and dedicated `expandPrimaryBranches` `ls-remote` use `DISCOVERY_GIT_TIMEOUT_MS` (5 min; not `countOpenLumpBranches`); `listRemoteHeadBranches` returns Result (`reason: 'timeout' | 'exit'`) — expand fails the tick only on timeout, other ls-remote failures skip the glob like empty; `countOpenLumpBranches` / `clean` treat `!success` as `0` / `[]`; no branch-workspace preflight. Lump-run hook in `withWorkspaceLockHooks` targets **`resolvedBaseBranch`** (not `resolvedDiscoveryBranch` except when they coincide); daemon discovery uses a separate call with **`scanBranch`** in `discoverDedicatedLumpsForScanBranch`. Preflight and other Lumpcode git mutations take **`gitCommonDirLock`** (`~/.lumpcode/git-common-dir-locks/`, busy code `gitCommonDirBusy`; daemon `wait`, manual `fail`) keyed by `git rev-parse --git-common-dir` — path locks alone do not cover the shared object DB
- Shared mode copy reuse: compare source vs copy `origin` URLs; `git remote set-url`/`add` on mismatch only (fresh `fs.cp` skips — inherited remote correct). `git fetch --all` alone cannot fix wrong `origin` URL
- No dirty-tree guard yet — dedicated mode can wipe uncommitted work
- `maximumNumberOfConcurrentBranches`: enforced only in `runLumpFromJsConfig` via **`evaluateTooManyOpenBranchesSkip`** (`countOpenLumpBranches` at execution workspace, `git ls-remote --heads origin` for `lump/<lumpName>/*`); **lump-wide** across all discovery/scan lines (not per scan branch); limit reached → `skipped` variant; not duplicated in phase 1

### Workspace locks (CLI-only)

- **`workspacePathLock`**: single namespace per `path.resolve` (`workspace-path-locks/`); **`workspacePathBusy`** failure; manual `run` `lockMode: 'fail'`, daemon `wait` (15 min then same code + `reason: 'waitTimedOut'`; re-log every 30s); atomic `wx` only (no FIFO v1)
- **`run` / `start`** call **`runLumpFromLumpName`** (phase 1) → **`runLumpFromJsConfig`** (phase 2); tests may call `runLumpFromJsConfig` directly with `jsConfig`
- **Phase 1** (dedicated): `preflightDiscoveryBranchWithLock` → load config + disabled soft skip; checkout keeps lock into phase 2; worktree releases after validation (parallel agents across worktrees; shared-git mutations still serialized by `gitCommonDirLock`)
- **Phase 2**: `withWorkspaceLockHooks` — baseBranch preflight at setup; checkout continuous hold; worktree hold execution through setup then release execution-path lock when setup fn returns (branch path lock remains)
- Phase-1 **`releaseLock`** handoff → adopted into `session.releaseExecutionPathLock` at **`runLumpFromJsConfig` entry**; `try/finally` + **`releaseWorkspaceLockSession`** releases on all early returns (including **`tooManyOpenBranches`**)
- Disabled lump soft skip in phase 1 must call **`releaseLock`** before return (phase 2 not invoked)
- **`--discoveryBranch`** on `run` / `lump-plan` / `lump-status` (not on `start`); **`resolveEffectiveDiscoveryBranch`** (discovery only, not `resolvedBaseBranch`); shared: `run` warn-and-ignore, inspect commands honor via `honorDiscoveryBranchOptInShared`
- **`discoverDedicatedLumpsForScanBranch`**: short-lived locked preflight per `scanBranch` with lock holder **`DISCOVERY_SCAN_LOCK_HOLDER`** (`__discovery__`); daemon tick re-runs phase 1 per lump
- `workspaceFileLock` is internal — barrel-export `workspacePathLock` only
- Force-killed daemons (`stop --force`) may leave path locks; next acquire removes stale locks when holder PID is dead — no stop-time lock cleanup
- Do not duplicate core planning in CLI for lock keys (no pre-run `getToDoContextList` or `branchFn`)

### Daemon

- One daemon model: every `start` discovers like today’s former global (dedicated: all primary-branch subticks), then applies optional `--include` / `--exclude` (`*` globs). Identity is **`daemonId`** (`~/.lumpcode/daemons/<project>.<daemonId>.daemon.*`); default unfiltered id `global` (reserved for unfiltered). Overlapping filtered daemons allowed (unique id); start gates on unique id + corrupt-meta fail-closed only. Multiple `--include` daemons on one dedicated clone under **worktree** are supported: path locks + **git-common-dir lock** (path then git order); worktree releases the execution-path lock after setup fn returns (not via `afterExec` when setup `command` is empty). CLI gates setup/teardown/add+commit/push under that lock via `makeGatedGitFns` (`gitAddCommitFn` / `gitPushFn` return Result; nullish Success = already done). Context status uses one locked `refreshRemoteTrackingRefs` (`git fetch --prune --no-write-fetch-head origin`) then `getContextStatus({ skipFetch: true })` — injected on `RunLumpInput` / `getToDoContextList`; CLI `getContextStatus` / `getContextStatuses` / `lump-plan` / `buildContextStatusRecord` take the same lock (`lockMode: 'wait'`)
- Auto-id: single exact include → that name (`name-2`…); multi/glob → `d-` + 6 hex; `--daemonId=global` with any filter fails. Deprecated `--lumpName` on start ≡ `--include=<name>` (warn); on companions ≡ `--daemonId`
- `start` detaches by default; companions: `stop`, `restart`, `daemon-log`, `daemon-status` (`--daemonId`, default `global`), `supervise --foreground`. `daemon-status` with no id flags **lists all** project daemons and adds `supervisor: { running, pid? }`. Supervisor files: `~/.lumpcode/supervisor/<projectName>.{pid,log,meta.json}` (not a daemon id, not under `daemons/`)
- `start` writes `~/.lumpcode/daemons/<project>.<id>.daemon.desired.json` before spawn (`projectRoot`, `daemonId`, `cronSetup`, optional include/exclude/maxParallelRun; no `--json`/`--verbose`). In-memory spec is **`StartDaemonRecipe`** in `startDaemonDesired` (`recipeFromDesired` is the only Recipe constructor; `fromMeta` / `toDesired` / `toMetaWrite` / `toForegroundArgs`; desired is `Omit<recipe, 'workspaceStrategy'>` plus optional `stopping`). Detached parent claims the PID file via `spawnDetachedLumpcodeWithPidFile` (`wx` + kill-on-fail + stub meta). `start` and `restart` share **`launchStartDaemon`** (util; explicit `Success<LaunchStartDaemonOutput> | Failure<LaunchStartDaemonFailure>`). `restart` snapshots **desired.json** then **`stopOneDaemon`** then launch (`fromMeta` only as legacy adopt). No snapshot (missing desired and unreadable meta): live pid → fail closed without stop; stale pid → **`unlinkBestEffort`** leftovers (same stale message as stop); missing pid → same missing message as stop — never invent a default recipe or run operator-stop just for messaging. `stop` / `restart` map operator stop results via **`stopOneDaemonCliFailure`**. `start` starts `supervise --foreground` if that project's supervisor PID is dead. Tests inject `skipEnsureSupervisor`
- Desired `stopping: true` = operator drain (idle `stop` / Ctrl+C / SIGTERM / `stop --all` / `--force`). Unlink desired **after** the process is confirmed dead so supervise cannot respawn mid-kill. OOM/`kill -9` leaves desired so supervise respawns. Busy single `stop`/`restart` still refuse `daemonBusy` and leave desired unchanged
- `stop --all` is project-scoped: mark all desired stopping first, drain/kill lump daemons, delete leftovers, then stop supervise. Only `stop --all` stops supervise (no `supervise-start` / `supervisor-stop`)
- PID/meta JSON for the scheduler is written by the **foreground** child (detached parent also writes a stub). Meta writes `daemonId`, `include`/`exclude`, optional `maxParallelRun`; never writes `lumpName` (read-only compat). Desired.json is source of truth; live pid with no desired is adopted as legacy
- Croner `{ protect: true }` + `await runTick()`; worktree concurrency = `--maxParallelRun` ?? `local.json.maxParallelRun` ?? `1` (checkout always `1`; CLI flag with checkout fails)
- **`discoverLumpNames`** / **`discoverLoadableLumps`** / **`discoverLoadableLumpNames`**: all lump dirs vs single-pass loadable `{ lumpName, jsConfig }[]` (optional `logger` warns invalid dirs); names-only wrapper — used by `start`, `validateDaemonLaunch`, `resolveTargetLumpNames`, `lump-status`, `discoverDedicatedLumpsForScanBranch`
- **`discoverDedicatedLumpsForScanBranch`**: dedicated discovery helper — locked preflight to `scanBranch`, then `discoverLoadableLumps`, then filter by `resolvedDiscoveryBranch`; used by daemon tick and `validateDaemonLaunch`
- **`validateDaemonLaunch`**: filesystem-only at start for every daemon (allowlist, duplicate-name); dedicated locked preflight per `primaryBranches`; dirs without config → `logger.warn` and skip; fail-fast on same-primary duplicate `lumpName`, unlisted discovery branch, discovery preflight failure
- Tick (dedicated): per primary-branch subtick → locked discover → include/exclude → run or no-op (empty match stays up); pass `effectiveDiscoveryBranch` into `runLumpFromLumpName`. Context `priority` is intra-run only. A lump-wide open-branch cap plus primary-first order can starve later scan lines (`tooManyOpenBranches`) while the primary still has todos or an open `lump/<lumpName>/*` branch. No `ignoredByGlobalDaemon` (removed)
- Manual `run`: no daemon PID gate — coordinates via workspace locks only (`lockMode: 'fail'` vs daemon `wait`); dedicated `dedicatedRestoreBranch` `git switch` in handler `finally` after lock release
- Default `stop` refuses when mid-run (`isDaemonMidRun` / `daemonBusy`) or when meta is missing/invalid (`daemonMetaCorrupt`); idle SIGTERM waits **`DAEMON_IDLE_STOP_WAIT_MS` (5s)** then **`stopOneDaemon`** (result cannot be `draining`). `--force` tree-kills with `graceMs: 0` and does **not** require readable meta. `stop --all` marks all desired stopping, then loops **`drainOrStopOneDaemon`** (mid-run → `draining`; corrupt meta proceeds; result cannot be `busy` / `metaCorrupt`), polls leftovers, unlinks, then **`stopSupervisor`** (pid + supervisor meta only; never `readDaemonMeta` / desired.json). Desired ids: `listDaemonIds({ kind: 'desired' })`. Path bundle: **`daemonSchedulerFiles`** owns modern paths, **`legacyGlobalDaemonSchedulerFiles`**, and **`unlinkSchedulerFiles`**. Supervisor / generic unlinks use **`unlinkBestEffort`**. `RunningDaemonInfo` is the file bundle plus `pid` and either `{ meta: DaemonMeta }` or `{ metaStatus: 'missing' | 'invalid' }` (`hasRunningDaemonMeta`). PID claim: `claimPidAndWriteMeta` (exclusive `wx` is private). Cleanup: `unlinkSchedulerFiles` (path bundle) / `unlinkBestEffort` / `removeOwnPidArtifacts` (`claimPidAndWriteMeta`). `installProcessShutdown` runs `onSignal` for OS signals, `shutdown()`, and `waitForShutdownOverride`.
- `readDaemonMeta` fails closed (`missing` / `invalid` / `io`) — never invent checkout/idle from a missing file; valid meta may still default omitted `workspaceStrategy` to `checkout`
- Alive PID + bad meta: `listRunningProjectDaemons` returns `{ metaStatus: 'missing'|'invalid' }` keyed by `daemonId` (legacy bare `<project>.daemon.pid` maps to `global`); `assertDaemonStartAllowed` / `start` refuse with `daemonMetaCorrupt`; `restart` snapshots desired.json (legacy: meta) then `stop --force` when meta is unreadable
- Foreground daemon arms native SIGINT/SIGTERM via **`installProcessShutdown`** (shared with supervise; drain calls `shutdown()`) **before** the first `runTick`, plus `installDaemonProcessGuards` (ignore SIGHUP with one log line — `stop` stays SIGTERM; `uncaughtException` / `unhandledRejection` log + `exit(1)` — lump command Failures stay in the Result path; blocking stdout/stderr); in-flight meta writer keeps an in-memory count and writes `baseMeta + inFlightLumpCount` (no read-merge); `busy` is deprecated read-only
- `daemon-log`: follows by default; `--noFollow` prints and exits; `--lines` limits initial output; daemon/supervisor logs are append-only with no rotation (`~/.lumpcode/daemons/<project>.<id>.daemon.log`) — lump `verbose` dumps full agent stdout and can grow unbounded; `stop --all` unlinks them as scheduler teardown
- Cross-lump `dependsOnContexts`: warns when `otherLump.baseBranch !== thisLump.baseBranch`
- Treat `.lumpcode/` configs and command modules as trusted executable code

### Command modules, presets, and TS transpile

- Custom commands in config `commands/` folders export `command`, `setup`, `teardown`; local config precedes global; probe **`.ts` before `.js`**
- Presets: `presets/<name>.js` only; installed to `~/.lumpcode/commands/presets/` via `installPresetCommands` (first `run`/`start`/`lump-plan` copies missing only; `reset-presets` overwrites). Plain ESM — no `@lumpcode/core` imports; Node builtins + relative `./utils/` only
- Lump-local `.ts` transpiles via **`transpileTypeScriptToCachedMjs`** (esbuild → `.lumpcode/.cache/transpile/<sha256>/<cacheKeyMs>/out.mjs`); bundle relative imports with `packages: 'external'`; post-process rewrites `import.meta.url`; **`ensureCacheGitignored`** on first transpile
- Use **resumable** (not "idempotent") for run behavior; presets persist chat/session id in `contextRunState` and `keepHistory`
- **Cursor/Copilot presets**: headless (`-p`, no user prompts); `.trim()` prompts, `null` for whitespace-only; resumable sessions in `<commandName>Setup`; Copilot denies agent `git commit`/`git push`
- Preset options (**`model`**, **`agentPermissions`**) on `lumpVariables`/`stepVariables`: **step overrides lump**, `model` defaults to `auto` for cursor/copilot (claude-code/opencode/codex omit the flag when unset — Claude Code and ChatGPT Codex both reject `auto`); step-only session keys `newChat`/`chatIdIndex`; Cursor `cursorConfigDir`; Copilot `writablePaths`/`denyShell` → `--allow-tool`/`--deny-tool`; callback `stepIndex` is `number` at depth 1 or `number[]` when nested
- Codex/OpenCode session bootstrap (`createCodexSession` / `createOpenCodeSession`): use **`execFileIgnoreStdin`** (end stdin) — default `execFile` pipes stdin and Codex hangs on `Reading additional input from stdin...`; Codex argv is `codex exec <options> resume <session> <prompt>` — parent `exec` options (`--sandbox`, `--add-dir`, `--model`) must precede `resume` (`codex exec resume` rejects `--sandbox` after positionals)
- `resolveImportable`: Vitest uses native `import(fileUrl)`; bundled code uses `dynamicImportForBundle` (Windows SEA requires `file://` URLs)
- Lump-config `*Fn` paths resolve relative to `.lumpcode/lumps/<lumpName>/`
- `promptTemplate` (`FilePathOrString`): resolve relative to `.lumpcode/lumps/<lumpName>/`; file ref only when entire string has no whitespace and ends with `.txt`, `.template`, `.prompt`, or `.md` and path exists (read once at config load; missing → fail); otherwise inline template text (`{VAR}` / `@{VAR}` unchanged). Prompt placeholders resolve from **context** variables, not from `lumpVariables`/`stepVariables` (those carry preset options and hook inputs). `command` file ref: no whitespace, ends with `.ts` or `.js`, exists under lump dir → `CommandModule` import; else tag lookup; lump tag `command` is auto-pre-registered (unique `Set` merge with `registerCommands` in `jsConfigToRunLumpInput`, not `getJsConfigFromLumpName`); `commandName` = literal config string; `registerCommands` tag-only for other names first seen in dynamic/recursive returns (unlisted nested tags still throw so `setup` is not skipped)
- `getCommandPath`: explicit local/global config paths only (no implicit `~/.lumpcode` fallback)
- CLI context status: `getContextStatuses` is the batch entry (`Map<string, ContextStatus>`, exported from `@lumpcode/cli-utils`); `getContextStatus` delegates to it for one name; default path does locked refresh then core `skipFetch`; `skipRefresh: true` when the caller already refreshed (`buildContextStatusRecord`)

### CLI framework

- Global options (`--json`, `--verbose`) on root program; subcommands read via `command.parent.opts()`; `lump-status` uses `--silent` for summary-only output
- `cliLog`: result envelope only; `--json` → one compact JSON line per invocation
- `addCommand`: injectable `exit(1)` on handler `Failure` and Zod parse failure
- Logger: `error` always prints (even with `--json`); `--json` suppresses other operational lines; CLI `--verbose` OR-merges lump-config `verbose`; `createCliLogger` prefixes `[lumpcode]`
- Shell escaping: `shellSingleQuote` from `@lumpcode/core` for user-controlled values; `shellBestEffort` for best-effort fragments
- Lump config has **no** raw `setupWorkspaceFn` / `teardownWorkspaceFn` knobs — CLI generates those from `local.json` + per-lump `baseBranch`. Optional `postSetupWorkspaceFn` / `postSetupWorkspaceCommand` (and teardown twins) run after generated setup / before generated teardown in the branch workspace; `lump-plan` skips them; not under `gitCommonDirLock` (do not put git mutations there)
- `LumpJsConfig` and related step/config types are dual-generic `<V extends LumpVariables = LumpVariables, SV extends StepVariables = StepVariables>`; authors refine with explicit type args at `defineConfig`/call sites (TS rarely infers from `lumpVariables`/`stepVariables` bags); defaults keep untyped configs working
- `LumpJsConfigSteps` is always an array of `LumpJsConfigStepsItem` (step object | `StepFn`/`LumpJsConfigStepsFn` | `promptTemplate` — no bare `promptFn`; those only via `prompt` or a step object); config `steps?: LumpJsConfigSteps | LumpJsConfigStepsItem` allows a solo item in JS/TS; private `prompt` solo type stays step | template | `promptFn`; `StepFn` exported via `cli-types`/`cli-utils`, input `Omit<PromptFnInput, 'stepVariables'>`, may return array or solo item; `normalizeSteps` always returns an array (solo fn → `[fn]`; other solos promote via the `prompt` wrap path; solo `steps` wins over `prompt`); JSON schema still requires an array

### Distribution, build, and CI

- **Primary install**: `npm install -g @lumpcode/cli` (Node 22+); unscoped `lumpcode` meta package optional, not user-documented; `install.sh`/`install-local.sh` are optional channels — `--name` for alternate symlink when npm + standalone coexist
- Recipe-based JS/TS configs need resolvable `@lumpcode/recipes` and `@lumpcode/cli-utils` under the project (global CLI does not provide package resolution) — add them to the day-to-day repo's `package.json` before the first push so a dedicated clone's `npm install` gets them; non-JS repos use a minimal root `package.json` + `npm install`, or skip recipes and write plain `config.json`/`config.js`
- `bin/lumpcode.js`: native binary when present, else `node dist/index.js`; `--version` reads `package.json` via static import in `main.ts`; `clean` removes only SEA outputs under `bin/` (not the launcher); gitignore `packages/apps/cli/bin/*` with `!packages/apps/cli/bin/lumpcode.js` so SEA sidecars (`esbuild`, schemas, presets, platform binaries) stay untracked — same launcher-only track for `packages/apps/cli-meta/bin/lumpcode.js`
